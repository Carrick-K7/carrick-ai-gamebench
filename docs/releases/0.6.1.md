# GameBench 0.6.1 — quality and auditability patch

This release refines the repository's **0.6.0 development baseline** without
changing its architecture or score meaning. The last earlier GitHub Release
was 0.4.0; the intervening 0.5/0.6 protocol evolution is recorded in
[CHANGELOG.md](https://github.com/Carrick-K7/carrick-ai-gamebench/blob/v0.6.1/CHANGELOG.md).

## What improved

- Task loading rejects duplicate or unsafe case IDs, empty/assertion-free
  browser cases, repeated/unscored case coverage, and build-case/category
  mismatches before an Agent is called.
- Texas Hold'em calibration now evaluates two positive controls and four real
  source mutants: incorrectly reopened short all-ins, dropped odd chips,
  missing wheel straights, and a broken native Check button. Both reference
  evaluations must share the same source hash and test vector; each mutant
  must fail its targeted case while keeping the build gate open.
- The leaderboard gives equal scores equal ranks, shows per-task scores and
  hard-gate failures, and exposes provider, thinking, and Campaign provenance.
  Missing scores do not receive invented ranks.
- Historical results and Campaigns are checked against their own release locks
  rather than the newest lock. `cagb --version` / `-V` reports `0.6.1`.
- Every full-check workflow explicitly installs Playwright Chromium and retains
  cold-cache starter smoke tests. Release retries verify existing evidence
  rather than overwriting it.
- The static-site workflow uploads a build artifact instead of triggering stale
  SSH deployment steps. Publishing this version does not deploy a service.

## What did not change

The four task IDs, versions, and content hashes are identical to 0.6.0, as are
seed `104729`, the 3600-second task budgets, one Agent invocation, one canonical
evaluation, source freezing, 100-point task weights, hard gates, and the
equal-weight Build mean. Result schema 2 and all canonical directory layouts
remain unchanged. There is no new service, Docker/verifier layer, or deployment.

`benchmark/releases/0.6.1.json` differs from the 0.6.0 lock **only in
`benchmark_version`**. Its full-file hash is necessarily new; existing results
and Campaign Plans retain their original 0.6.0 identities. Results are not
re-scored, relabeled, or automatically merged across versioned leaderboards.

No 0.6.1 Campaign or model measurement is fabricated for this release. New
Official measurements require a newly preregistered and committed 0.6.1 plan;
old single-use cells must not be reused. Existing 0.6.0 raw evidence remains
checkable with `cagb check --run runs/0.6.0/<series-id>`.

## Validation and remaining limits

Release verification runs `pnpm check`, including type checks, unit/integration
tests, builds, release/result checks, cold-cache installation, and real frozen
archive/browser calibration. The operator also runs `pnpm cagb doctor` for the
actual install/build/preview/Chromium preflight before publishing.

GameBench measures one observed public-contract delivery per task, not fun,
visual quality, hidden generalization, or statistically stable model ability.
Two reference evaluations are a repeatability smoke check, not independent
Agent samples; four mutants are not complete mutation coverage. Cross-Campaign
score differences remain descriptive.

Known outcome-affecting issues, including object-key-order-sensitive equality
and the legacy `$CAGB_SEED` prompt/runtime mismatch, are documented rather than
silently changed in this patch. They require a future Benchmark minor release.
See the [design review](https://github.com/Carrick-K7/carrick-ai-gamebench/blob/v0.6.1/docs/benchmark-design-review.md).
